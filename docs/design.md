# Hyper Chamber design

The product is a compact Dhalsim compendium, not a lesson sequence. The interface pairs a searchable reference browser with a complete selected entry. Filters do not change the selected entry: active playback and personal context remain stable while browsing. Focus mode removes the browser for use beside the game.

Charcoal, warm paper and restrained lime create a precise reference instrument. Condensed headings contrast with readable sans-serif labels and monospace input notation. Source footage supplies the main imagery. There are no invented statistics, rewards or completion thresholds.

Each entry separates type, situation and outcomes. Persistent notation precedes the replay and annotated filmstrip; frame selection pauses and seeks the actual local clip. Playback is explicit, muted initially, with native controls, looping and speed controls. Personal favorites, status and notes are local to the learner and visually separate from source verification.

Search, type, situation, saved state and entry selection are reflected in the URL. Entry selection creates history; filter edits replace the current history entry. Backups merge by entry ID with imported values replacing matching personal entries.

On narrow screens the reference browser becomes a horizontally scrollable card strip. On wider screens the notation panel remains visible while reading the detail; focus view supports a narrow game-adjacent window. Native dialogs provide notation help and backup controls. Controls have visible focus states and content does not depend on color alone.

Structure-only inspiration supplied by the research pass: [Zoom search and tagged clips](https://mobbin.com/screens/8ac631df-2124-44da-8199-2346d67375ac), [Vimeo result filtering](https://mobbin.com/screens/61a592c7-dc5b-40ce-bfb2-51498a6b68dc), and [Loom saved navigation](https://mobbin.com/screens/f2cf240e-0a9c-4935-ac4a-20c76c231c8d). These inform navigational conventions rather than styling. No OpenDesign integration was found in this session; local OpenDesign usage was not tested. Design is implemented natively in Svelte and CSS.
