# Hyper Chamber design

The product is a compact Dhalsim compendium, not a lesson sequence. The interface pairs a searchable reference browser with a complete selected entry. Filters do not change the selected entry: active playback and personal context remain stable while browsing. Focus mode removes the browser for use beside the game.

The MVP adopts Chamber: ivory, ink and aged brass, with the Hourglass H mark. Flat tiles and shared edges group references and controls. Condensed headings contrast with readable sans-serif labels and monospace input notation. Source footage supplies the main imagery. There are no invented statistics, rewards or completion thresholds. Semantic color roles live in `apps/web/src/app.css`; inverse input surfaces have explicit text, accent and focus colors.

Each entry separates type, situation and outcomes. Persistent notation precedes the replay and annotated filmstrip; frame selection pauses and seeks the actual local clip. Playback is explicit and silent. Tap the picture to play or pause; drag horizontally to inspect relative to the grab moment, then release to hold the result. Vertical touch movement scrolls the page. The timestamp and progress line appear only during inspection or keyboard focus. A compact toolbar keeps playback, replay, loop, speed and click-to-nudge controls available. Loop preference is remembered separately from learner data; native looping runs only during playback so a paused end inspection stays in place. Native controls provide the no-JavaScript fallback.

The video surface is a keyboard-operable button, and player shortcuts remain scoped to focused clip controls. A non-live position description and a polite announcement after an explicit seek or pause provide timing feedback without narrating continuous playback. The clickable key moments and nudge buttons provide alternatives to dragging. Personal favorites, status and notes are local to the learner and visually separate from source verification.

Input sequences use one ordered path of moves, with each authored label and cue beside its notation. SVG connectors show order only; they do not imply a cancel, a link, a timing window or a branch. The plain-text sequence remains available in a disclosure. Short paths can run horizontally when the panel has room; longer paths stay vertical. Semantic HTML carries the sequence, so the reading order and text remain available independently of SVG. Move nodes do not seek the video: input steps and captured frames have no authored mapping yet. Future timing or transition annotations need reviewed content before they can change a connector's meaning.

Search, type, situation, self-reported practice status, saved state and entry selection are reflected in the URL. Entry selection creates history; filter edits replace the current history entry. On mobile, choosing a reference focuses and reveals its heading. Backups merge by entry ID with imported values replacing matching personal entries; unknown IDs remain preserved while visible saved counts are scoped to the current library.

On narrow screens the reference browser becomes a horizontally scrollable card strip. On wider screens the notation panel remains visible while reading the detail; focus view supports a narrow game-adjacent window. Native dialogs provide notation help and backup controls. Controls have visible focus states and content does not depend on color alone.

Structure-only inspiration supplied by the research pass: [Zoom search and tagged clips](https://mobbin.com/screens/8ac631df-2124-44da-8199-2346d67375ac), [Vimeo result filtering](https://mobbin.com/screens/61a592c7-dc5b-40ce-bfb2-51498a6b68dc), and [Loom saved navigation](https://mobbin.com/screens/f2cf240e-0a9c-4935-ac4a-20c76c231c8d). These inform navigational conventions rather than styling. Design is implemented natively in Svelte and CSS.

For the sequence refinement, [Attio](https://mobbin.com/screens/b1d64fe7-82a9-42dd-9487-6385ac347cc6) and [incident.io](https://mobbin.com/screens/45365384-2ea7-4a55-bb83-2384579937f5) show vertically connected steps with information attached to each step. Those workflow editors supply structural examples only; Hyper Chamber keeps its existing palette, type and read-only reference behavior. The horizontal adaptation and text disclosure are design decisions for this compendium.
